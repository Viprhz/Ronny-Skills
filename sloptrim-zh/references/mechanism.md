# 检测器内部机制

解释「它到底怎么算的」、或要动计分逻辑时读这份。改阈值前先读
`calibration-corpus.md`，两件事别混。

**先把源码读准再开口。** 用户问「某个指标是什么意思」时，读那个函数本身，
再用他自己语料里的真实数字举例——不要凭印象描述流程。机制说错比不解释更糟。

## 一、触发层（plugin，非阻塞）

```
我调用 write_file / patch
        ↓
摘出被写文件的绝对路径
        ↓
扩展名在白名单？（.md .mdx .markdown .txt .text .rst .tex .org .adoc
                    .docx .pptx .xlsx .odt .epub .ipynb …）──否─→ 跳过
        ↓ 是
文件名是 skill.md / agents.md / claude.md / memory.md ？──是─→ 跳过（脚手架不算交付物）
        ↓ 否
体积：纯文本 ≤512 KB，压缩包 ≤4 MB ──超限─→ 跳过
        ↓
读出全文（docx/xlsx 走 zipfile 解 XML）
        ↓
汉字数 ÷ 字母数字数 ≥ 0.2 ？
    是（中文/中英混排）→ detect_zh.py    否（英文）→ detect.py（上游 71 条）
        ↓
score 0-100 + band
        ↓
档位门槛：full 模式 ≥40 分才报，strict ≥20 分才报 ──不到─→ 静默
        ↓
把报告追加到工具返回结果末尾（文件内容一个字没改）
```

要点：

- **非阻塞**。文件先正常写入，报告只追加在结果里，模型自己决定要不要改。
- **路由是按比例判的，不是按语言识别**。一份中文文档如果路径、代码、英文标识符
  占绝大多数，汉字占比可能压到 0.2 以下而被误路由到英文检测器。判不准时用
  `_is_chinese_text` 当场验，别看输出标签猜。
- **改了 detector 或新建 skill 后必须重启 Hermes**：`_load_zh_detector` 首次加载
  失败会把 `_zh_detector_loaded` 置 True 且不再重试，整个进程生命周期内中文都
  静默落到英文检测器。

## 二、清洗链（`scan()` 开头）

```
原始 markdown
  ↓ strip_quoted_spans          引文/代码块里的字不算作者文风
  ↓ _strip_feishu_tables        <lark-table>…</lark-table> 【整块连内容删】
  ↓                             + <lark-td>/<at>/{align=…} 去标记
  ↓ strip_markdown_furniture    复用上游：标题、粗体、列表、链接语法
  ↓ zh_count = 汉字数 + 英文词数 + 数字个数
  ↓ per_k = 字数 ÷ 1000          所有密度都以它为单位
```

**表格必须整块删。** 只剥标签会让每个单元格变成孤立短段落（单词、单元格内嵌的
编号列表、重复表头），被当散文统计，制造大片假「退化重复」。

## 三、四组判据

| 组 | 条数 | 进分数？ | 说明 |
|---|---|---|---|
| 词表（soft 8 / strong 11） | 19 | 是 | 密度 ≥ 各条阈值才算命中；动词类附近 ±12 字有具体数字时豁免 |
| 机器痕迹（decisive 6 / defect 2） | 8 | decisive 是 / defect 否 | decisive：聊天残留、知识截止、引用标记泄漏、AI 跟踪参数、同形异码、退化重复；defect：零宽字符、占位符残留 |
| 结构性（rhythm） | 3 | 是 | 段首重复、句长单调、段落等长 |
| 只报告（report） | 7 | 否 | 破折号（含单行密集）、括号插入语、引号造词、对冲堆叠、加粗小标题列表、加粗过多、表情符号 |

**词表判据只看密度，没有「绝对次数 ≥N 也放行」的例外。** 中文信息密度远高于
英文，同一绝对次数在 200 字和 5000 字里意义完全不同。短文本天然受保护：
200 字里命中 1 次就是密度 5，早超阈值。加例外只会让长文档里的领域术语误触发。

**只报告的三条为什么不计分**：破折号、括号插入语、引号造词在英文里是 AI 特征，
中文里本来就是正常标点，人写也用得很凶，硬计入会大面积误伤。

## 四、计分公式

三项相加，各自封顶，总分封顶 100。

```
A 内容项  封顶 48
   diversity    每「族」只计一次（family = key 前缀）
                decisive +16 / strong +10 / soft +2.5
   density_bonus = min(10, 内容负载 ÷ max(字数,150) × 1000)
                内容负载 = Σ 权重 × min(命中次数, 5)
                权重 decisive 3.0 / strong 1.6 / soft 1.0
   A = min(48, diversity + density_bonus)

B 节奏项  封顶 18
   每个 rhythm 命中 +4
   句长项 = max(0, min(1, (0.45 − cv)/0.45)) × 10      cv 为 None → 0
   段长项 = max(0, min(1, (0.40 − pcv)/0.40)) × 8     pcv 为 None → 0
   B = min(18, 命中数×4 + 句长项 + 段长项)

C 词汇项  封顶 20
   C = min(20, max(0, 空洞大词密度 − 3.0) × 1.8)

score = min(100, A + B + C)
```

然后用地板规则往上抬（防「命中很多但分数很低」）：

```
decisive ≥2 族                  → 至少 65
decisive 1 族 且 ≥150 字          → 至少 45
<150 字：命中 ≥3 族 → ≥45；≥2 族 → ≥25
≥800 字：命中 ≥5 族 → ≥45；≥3 族 → ≥25
```

## 五、档位与可信度

```
band        0–20 clean │ 21–40 light tells │ 41–60 mixed
            61–80 heavy tells │ 81–100 pervasive tells

confidence  <120 字        none        一个短语就能翻档，当噪声看
            120–299 字     low         低于 300 字地板
            300–799 字     low/moderate  且命中 ≤1 族时为 low
            ≥800 字        high
```

**分数和可信度必须一起读。** 高分 + `confidence=low` + 字数很小，基本是抽样噪声，
不能当结论。

## 六、改哪层验哪层

| 改了什么 | 必须重跑 |
|---|---|
| 任一条密度阈值 | 夹具分离 + 468 篇外验 |
| 清洗链（表格/引文/装饰） | 468 篇外验（假阳性会成规模暴露）+ 15 篇 docx |
| 计分权重或地板规则 | 夹具分离（分离度会直接变） |
| 某条正则 | 拿一批真实复合词单独反测，再跑全量 |
| 统计类门槛 | 夹具分离（代价落在短 AI 样本上）+ 灰区文档逐篇复核 |

改完统计类判据要**两面对账**：目标假阳性降了多少分，分离度缩了多少，
两个数同一次报给用户，让他知道代价再拍板。
