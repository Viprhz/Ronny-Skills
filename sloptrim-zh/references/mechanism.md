# 检测器机制

## 范围先于评分

`scan()` 调用 `text_scopes.prepare_scopes()`，检测与字符清洗共用受保护范围：

1. 用固定上游的 Markdown 识别器保护围栏代码、缩进代码、行内代码。
2. 保护 Markdown 引文，以及中文弯引号/直角引号包住的逐字内容。引用里的潜在套话不代表当前作者文风；需要编辑引用时应由用户另行明确范围。
3. 排除 YAML 元数据，提取飞书/HTML 与 Markdown 表格单元格。
4. **词汇范围**包含正文、标题、列表及表格单元格；**节奏范围**排除标题、列表、表格、代码和引文。
5. 格式与链接线索保留可编辑区域的原标记，避免先去链接语法后漏掉 URL 参数。

这不是完整 Markdown/HTML 解析器。非常规嵌套、内嵌 HTML 代码等需人工复核；不能把覆盖率当作完整解析证明。

`_metrics.coverage`：`input_units` 是输入文字单位，`analyzed_units` 是参与词汇检查的单位，另有 `prose_units/table_units/table_cells/protected_units/rhythm_units`。单位为汉字按字、英文按词、数字按组计。`analysis_coverage` 为分析单位/输入单位，格式标签与 URL 也影响分母，不能当作字节级精确覆盖率。

## 计分与来源核查

通过 `--list-patterns` 获取当前规则、密度阈值与档位，数量不另行维护。

- `soft/strong`：中文表达线索；密度达到阈值才计分。
- `decisive`：聊天标记、特定来源参数等强编辑线索；单族最低 45 分，两族最低 65 分。**短文也会抬分，但可信度仍不足**。复制链接、工具链和人工引用都可能产生残留，不能据此断定作者。
- `rhythm`：仅对散文计算，句长至少 5 句、段长至少 4 段。CV 不是写作验收目标。
- `report/defect`：只报告，不计分；包括标点/格式、占位符、编辑器残留和**来源/权威引用待核查**。没有联网查证，不称“虚假”。

少数动作类规则允许具体指标豁免：同一句内，动作与明确数量/结果指标有关联才豁免；年份、日期、版本和编号不能单独背书。仍是正则启发式，不能代替语义判断。

内容分 = min(48, 各族多样性权重之和 + min(10, 内容负载/有效长度×1000))。
节奏分封顶 18，空洞大词密度附加分封顶 20，然后应用族数与强线索的最低分规则。
精确常数与顺序以 `ai_tell_score()` 为准；对外解释应引用当前代码与运行结果。

## 状态与可信度

- 抽取失败：CLI 返回 2，`extraction_status=error`，`ai_tell_score=null`，`band=unassessed`。
- 文本可读但全是保护内容、没有可分析文字：`assessment_status=no_analyzable_text`，字数为 0、分数 null；CLI 返回 2。
- 正常扫描：`assessment_status=ok`。分数之外仍要看置信度与覆盖范围。
- 可信度 `none/low/moderate/high` 根据长度和命中族数判断样本是否够用，**不是经过校准的置信概率**。不少于 800 单位时为 high，也不能保证规则正确。

## 字符与文件

`clean_protected()` 先隐藏保护内容，在正文上调用固定上游 `clean_text()` 并清理汉字旁的意外 ZWSP，最后恢复保护内容。两次字符处理都发生在恢复之前。功能性 Unicode、组合 Emoji、代码和逐字引文不应被清理。

默认内置组件和禁用外部上游时共用同一后端，没有阉割版回退。显式指定外部后端时由调用者负责兼容性；报告显示 `external`。

压缩文档逐成员检查大小与解析状态，表格保留单元格边界，段落与行内代码样式分别保护；任何候选章节失败都拒绝给出成功评分。读取时验证包与 XML，UTF-8 文本严格解码。损坏、空文件、不支持格式返回错误。抽取后的文本不能用于重建原 Word/表格/演示文件；版式与富文本修改应交给对应编辑器。

插件是独立集成，不随本目录更新：调用方需处理 `unassessed/null` 状态、低可信度和模块缓存。这里不承诺任何外部插件的阈值、触发方式或热加载行为。
