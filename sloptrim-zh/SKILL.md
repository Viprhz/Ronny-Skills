# Sloptrim-zh — 中文去 AI 腔

给中文文案做「去 AI 腔」：用一套**中文专属**的确定性检测器打分定位问题，
再按规程改写，同时保住每一个事实、数字和专有名词。

检测器是纯 Python 标准库脚本，**不调用模型、不联网**。

## 何时用

- 用户说「去 AI 味」「去 AI 腔」「这读着像机器写的」「改得像人写的」。
- 中文交付物（周报、PRD、SOW、述职、汇报、纪要、对外文档）写完要发出去之前。
- 一份中文稿子命中率高，需要定点修。

**不要用于**：代码、配置、commit message、翻译原文、用户明确要求逐字保留的文本。

## 前置

```bash
DETECT="$HOME/.hermes/skills/productivity/sloptrim-zh/scripts/detect_zh.py"
python3 "$DETECT" --help
```

路径不对就用 `search_files`（target `files`，pattern `detect_zh.py`，path `~/.hermes/skills`）。

## 怎么跑

```bash
python3 "$DETECT" 稿子.md              # JSON 报告：命中项 + 分数 + band
python3 "$DETECT" --clean 稿子.md      # 字符层清洗后的文本（不改字）
python3 "$DETECT" < 稿子.md            # 从 stdin 读
```

JSON 里有：每个命中项的 `count` / `density`（每千字命中数）/ `samples`（上下文片段），
一个 `_metrics` 块（`zh_chars` / `sentences` / `length_cv` / `paragraph_cv`），以及
`ai_tell_score`（0-100）和 `ai_tell_band`。

**判读分数**：分档 `clean`（≤20）/ `light tells`（≤40）/ `mixed`（≤60）/
`heavy tells`（≤80）/ `pervasive tells`（>80）。

分数是**分诊启发式**，描述文本不描述作者。不能用来指控任何人。

`--clean` 只做字符层清洗（去零宽字符、折叠同形异码、规范空格、修剪尾随空白），
**一个正文字都不改**。输出到**新文件**——对 `.docx` / `.epub` / `.odt` 它输出的是
提取出的纯文本，覆盖原文件会毁掉它。

## 快速对照

| 需要 | 动作 |
|---|---|
| 打个分看看 | `python3 "$DETECT" 文件.md` |
| 定点修 | 读 JSON 的 `samples`，只改那些片段 |
| 清字符 | `python3 "$DETECT" --clean 文件.md > 干净.md` |
| 看改写范例 | 读 `references/patterns-zh.md` |
| 有哪些命中项 | 见下方*命中项目录* |

## 程序

1. **选风格，不问用户**。读内容自己定：
   - 事实性 / 说明性 / 技术文档 → **平实清晰**（短句、具体名词、主动动词）
   - 第一人称 / 有观点 → **自然随笔**（口语、句长起伏、有具体场景）
   - 对外正式（公告、述职）→ **正式书面**（克制、句式完整、无口语）
   - 叙事 / 复盘 → **讲故事**（细节先出场，结论后到）
   用户点名了风格或给了写作样本，以用户的为准。

2. **定尺度**。保守（只改明显的 AI 腔，不动句式结构）／激进（允许重写句子顺序）。
   事实性、说明性、命令式内容 → 保守。已有第一人称声音的 → 可激进。

3. **打分定档**。先看 `_metrics.confidence`：`none` / `low`（不足 300 字）时分档仅作参考，直接按第 4 步逐句审读。可信度足够时：`clean`（≤20）：只做字符清洗和定点微调，**不要重写**——
   一份本来就写得好的稿子，重写只会毁掉它的声音。`light tells`（≤40）：定点改 +
   修节奏。`mixed` 及以上：往风格档位上重写。

4. **找出需要语义判断的项**。检测器抓的是可枚举的表面特征；下面这几类要靠读：
   - **空洞但语法完整的句子**——每个名词都站得住，合起来什么也没说
   - **排比成瘾**——连续三句同构，说的其实是一件事
   - **段落模板化**——每段都是「总—分—总」或以「这说明…/由此可见…」收尾
   - **复述题目与自问自答**——首句原样复述需求，或「为什么这么做？因为…」
   - **列表化过度**——本该两句话说清的推理拆成三五个 bullet
   - **情感扁平**——「感到一阵深深的悲伤」这种贴标签式表达
   - **细节造假**——引文格式对但内容是编的，定义听着周全但套谁都行
   读 `references/patterns-zh.md` 拿该 pattern 的具体说法和改写前后对照。

5. **记下必须保住的内容**。数字与单位（`0.19`、`340 kg/m³`、`55%`）、
   专有名词、产品名、版本号、人名、日期、引用、领域术语。
   还要记下**实体清单装不下**的东西：
   - 哪个结论是**引述别人的**，哪个是**作者自己的**
   - 哪些话是**有保留的**（可能、大致、在一定条件下）
   - 哪个数字**挂在哪个名词上**
   - 原文多少字（改写后不能超过 1.25 倍）

6. **改写**。往风格档位上靠，但只动 AI 腔的部分。

7. **反钝化自审**（内部，不打印）：重跑检测器，问两个方向——
   还哪里像 AI？**是不是改平了**？中文里「改平了」的信号是：
   句长开始整齐、段落长度趋同、口语词全没了、每段都是三句。
   **改平了的稿子和 AI 腔一样像机器写的**。只修 offending 的片段，最多两轮。

8. **核事实**。每个数字、人名、单位、日期、引用都还在，且还挂在同一个名词上。
   没有编造原文没有的引文、来源、日期、人名。缺信息就保持含糊，不要补。

9. **交付干净文本**（见下）。

## 输出契约：沉默

这个 skill 不谈自己。它交回改好的文本，别的什么都不说。

**永远不要输出**：跑过了的宣告、风格/档位说明、分数或报告、草稿、自审笔记、
「事实已保留」这类声明、修改清单、前言、结尾客套。

**只输出**：
- 用户给了正文 → 直接给最终文本，前面后面都不加东西
- 用户给了文件路径 → 纯文本（`.md` / `.txt` 等）就地改写，然后**一行**：文件路径；`.docx` / `.epub` / `.odt` / `.ipynb` 不可把纯文本覆盖回原文件（会毁掉压缩包结构），写出到同名 `.md` 并输出新路径
- 作为交付前的一道关卡用 → 直接交付干净文本，不提这一关跑过

每一步内部照跑（检测、档位判定、自审、字符清洗）。沉默是说**不打印**，
不是说不做。

只有这几种情况打破沉默：
- (a) 某个事实保不住，或某个生僻词无法核实——一行说明，然后给文本
- (b) 用户**明确要**分数、报告、风格选择或 diff
- (c) 高风险第一人称交付物（求职信、个人陈述），文本后可以加**恰好一行**
  提供换语气选项

## 风格档位

去掉 AI 腔是一半，另一半是重建成一个真人会写的声音。每个档位是**正向目标**——
它不改变「哪些要去掉」和「什么要保住」，只定节奏、语域、标点和段落形状。

**1. 平实清晰（默认）**——现代非虚构。短词优先、砍掉赘语、具体名词加主动动词、
一段一个意思。适合周报、PRD、SOW、说明文档、对外沟通。**保守档**。

**2. 自然随笔**——第一人称、口语、有旁逸斜出；对事实有反应而不只是复述。
只给已经有个人声音的文本用，别硬套到说明性内容上。**激进档**。

**3. 正式书面**——公告、述职、对外正式文件。克制、句式完整、不用口语、
不夸张。**保守档**。

**4. 讲故事**——先给场景和细节，结论后到。读者自己会补上省略的逻辑。
适合复盘、纪要、案例。**激进档**。

### 贴着用户自己的声音走

用户给了写作样本，就从样本取目标声音，不要套档位：量句长及其波动、正式程度、
段落开头方式、标点习惯、口头禅——然后往这些习惯上重建。没有样本 → 按第 1 步分类。

## 中文事实保全

**每次改写都必须活下来**：数字与单位、专有名词、产品/版本名、人名、日期、
引用、领域术语、连字符技术词。

**可以换说法**：对冲词（可能、通常、在一定程度上）、泛化的被动句、
抽象性质名词（前提是领域术语还在）、填充性副词。换掉对冲词保留了限定性，
删掉最后一个对冲词就把有限定的断言变成了绝对断言。

**绝对不许编**：日期、统计数字、引文、人名、原文没有的来源。具体信息缺失就保持含糊。

**永远不要改变一句话断言了什么、属于谁、有多少**：

- **不能把测量变成断言，或把断言变成测量。**「实测 23.2 lb」是作者的观察。
  「标称重量 23.2 lb」是转述厂商。永远不要给平铺直叙的东西加「标称」「据称」
  「疑似」，也不要从本来就有归属的话里删掉它们。
- **不能删掉对冲。**「存在过度诊断的风险」删掉「的风险」就变成了断言。
  对冲**堆叠**是命中项——去掉一个，永远不是去掉最后一个。
- **不能反转批评。**「它的小尺寸让它更像威慑而非真正的防盗」是抱怨；
  读成「这锁之所以有效是因为它小」就把作者的判断倒过来了。
- **不能把数字换到别的名词上。**「30 小时续航」不等于「30 小时降噪」。
  每个数字都要留在它原本度量的东西上，尤其是标题、主题行和图注。
- **不能丢关系。**「A 第一、B 第二、C 第三」不只是一个列表。
  「两件事同时跑」不等于「先后跑」。排名、时序、否定、限定都要保住。
- **不能重写占位符。**`[姓名]`、`{{first_name}}`、`【待补】` 是合并字段。
  照原样留着，或者整份别动。
- **不能加料。**改写只修已有的东西。超过原文 1.25 倍字数（按检测器 `_metrics.zh_chars` 前后对比）就是新写的。
  砍可以，扩不行。档位里说的「补一个转折句」「举个例子」意思是
  **把已有的材料重新组织**，不是**另写一段**。

**领域正确性检查**：改写引入的每个专业词、成语或四字组合都必须符合该领域的真实用词习惯（如不可把「召回率」改成「回收率」）。
**真实但用错的词，比错别字更糟。**

## 正向写法（去掉 AI 腔之后往哪改）

- **去名词化**：「进行了优化」→「优化了」，「实现了 30% 的提升」→「提升了 30%」，「做出了调整」→「调了」。
- **砍「的」字链**：一个名词短语里最多留一个「的」；「对用户真实场景的深刻洞察」→「看清用户在哪一步卡住」。
- **主语落到人或具体事物**：「相关工作得到推进」→「张伟周四把登录接口调通了」。
- **四字格节制**：一段话里成语和四字短语不超过两处。
- **长短句交错**：三五个字的短句可以独立成句；最后一句落在具体事实或判断上，不用展望或口号收尾。

检测器覆盖 20 类计分词表，外加机器痕迹、统计类与只报告项。每类在 `references/patterns-zh.md` 里有具体说法清单和改写前后对照。
对于「推进/打造/实现/进行/降低…成本」等动词类规则，命中片段前后 ±12 字内有具体数字或量词单位时自动豁免（有数字托底的是具体事实，不算空转）。

- 47. 聊天机器人残留（好的！以下是为您…／希望对您有帮助／如有其他问题欢迎随时告诉我）
- 50. 知识截止声明（截至我的知识截止日期…）
- 64. 聊天引用标记泄漏（`【1†source】`、`contentReference[oaicite:0]`、`citeturn0`）
- 65. AI 跟踪参数（`utm_source=chatgpt.com` 等 AI 来源参数；普通 `utm_source=wechat` 不算）
- 66. 同形异码字符（`с` 冒充 `c`）

- 62. 零宽字符（飞书富文本导出常在 `**：` 旁塞 `U+200B`，报告并由 `--clean` 剥除，不计入 AI 分）
- 63. 占位符残留（`【待补】`、`{{...}}`、某某某）

### 统计（rhythm）
- 40. 句长单调（`length_cv` < 0.35，**且 ≥5 句**；不足 5 句 `cv=None`，不判不计分）
- 42. 段首重复
- 44. 段落长度一致（`paragraph_cv` < 0.40，且 ≥4 段）

- 33. 加粗小标题列表（`**小标题**：`）、56. 加粗过多、57. 表情符号——飞书 SOW/PRD 常用格式，报告供改写参考，不直接加分
- 54. 对冲堆叠（同句 ≥2 个不同对冲词）——对齐上游归入 report，提醒改写时删减冗余对冲，保留最后一个限定词

## 中文专属的坑（都已在检测器里处理）

上游英文检测器直接拿来跑中文是**完全失效**的——实测中文 AI 腔得 0 分、
`clean`。原因有三层：

1. **分词**：`count_words` 用 `\b\w+\b`，中文一整句算 1 个「词」。
   → 中文按**字**计（汉字按字、英文按词、数字按个数）。
2. **分句**：`split_sentences` 按 `.!?` 切，中文句号 `。` 不算边界。
   → 中文按 `。！？；…` 切。
3. **词表**：71 条 pattern 全是英文短语。
   → 中文另建 17 类词表。

另外两处中文特有的误伤，也已修掉：
- **退化重复**不能用 6 字 n-gram（中文常用词组合天然重复，`.googleapis.com`
  这类技术串重复 28 次就够触发）→ 屏蔽 ASCII 串 + 12 字 n-gram + 只跑散文段落。
- **飞书表格要整块连内容一起删**，不能只剥 `<lark-table>`/`<lark-td>` 标签：
  剥完标签每个单元格变成孤立段落（短词、单元格里嵌的编号列表、重复的表头），
  被当成散文——实测一份 SOW 因表头重复 11 次、一份效果文档因图注重复 73 次
  被判「退化重复」。468 篇真实飞书文档实测：只剥标签时 353 篇误判，整块删除后
  只剩 1 篇（真阳性，图注确实重复了 73 次）。
- **段首重复**不能算说话人标签（对话逐字稿里「罗：」重复 8 次）和日期开头
  → 排除标签形态和纯数字开头。

**命中判据只用密度（每千字），不要加「绝对次数 ≥N 也放行」的例外**：中文信息密度
远高于英文，同一绝对次数在 200 字和 5000 字里意义完全不同。短文本不需要例外——
200 字里 1 次就是密度 5，天然超阈值；加了例外反而让 2000 字文档里出现 3 次的
领域术语（如「闭环」）误触发（实测把人写的周报规范、岗位 JD 判成 AI 味）。

实测**全部计分 pattern 的合计密度**：
- 真实中文人写文本 ≤ **2.23** 次/千字
- 模型生成文本 ≥ **26.2** 次/千字

每条 pattern 的单独阈值都落在「人写实测最大值」与「AI 实测最小值」之间，
例如空洞大词：人写 ≤0.28，AI ≥5.18，阈值取 3.0。

## 中文没有对应物的上游 pattern

缩写、contraction absence、title case、em-dash overuse、curly quotes、缩略语堆叠
——这些在中文里要么不存在，要么是正常用法，**不做检测**。破折号降为只报告。

## 校准与验证

```bash
cd ~/.hermes/skills/productivity/sloptrim-zh/tests
python3 validation_corpus_zh.py
python3 test_probes_zh.py
```

人写侧用真实语料（用户 Obsidian 日记 / OKR 自评 / 工作日志 / 对话剪藏 / 竞品分析），
AI 侧按公开的中文 AI 腔特征仿写。检验标准：**AI 组最低分 > 人写组最高分**，且 28 条探针回归全部通过。

人写侧有一组 `BUSINESS`（真实飞书业务文档：SOW、岗位 JD、产品线战略，截到 ~220 字
与 AI 样本同量级）。这组是「术语 ≠ AI 腔」的边界检验：SOW、JD、战略这类体裁本身
密集使用「闭环/赋能/可量产/差异化」，仪器不得把它们判成 AI 味——改任何阈值后，
这组分必须仍落在人写侧。

当前实测：人写组最高 17，AI 组最低 48，**间隔 31**；`test_probes_zh.py` 28/28 通过。

大规模外验证（防夹具过拟合）：对 468 篇真实飞书知识库文档（SOW/战略/纪要，
≥800 字）跑检测，423 篇 0 分，唯一 ≥25 分的是真阳性（图注重复 73 次）。

阈值不是拍脑袋定的——改 `_ZH_PATTERNS` 里任何一条的密度阈值，都要重跑这个检验，
确认分离还成立。**分离破了就是回归**，说明阈值该重校准了。

**收紧判据必须两面对账。** 为了让某一类假阳性闭嘴而收紧统计类判据时，代价会落在
另一半：短 AI 样本也失去同一个信号，分离度会缩。这不是「副作用可以忽略」，
而是要报给用户的一笔账——「目标样本从 X 分降到 Y 分」和「分离度从 A 缩到 B」
必须同一次说清，让用户在知道代价的前提下拍板，而不是只看到好处。
只报改善不报代价，等于替他做了决定。

三层校准的完整配方（夹具分离 → 飞书 468 篇外验 → 本地 docx 抽取）、
夹具新增样本的量级与体裁规矩、拉单篇命中原文的代码，见
`references/calibration-corpus.md`。

检测器的内部机制——触发链、语种路由、清洗链、四组判据、计分公式与档位/可信度——
要讲给用户听、或要动计分逻辑时，见 `references/mechanism.md`。先把机制读准再解释，
不要凭印象描述流程。

### 灰区文档怎么判（大规模语料校准的第二步）

跑完语料拿到分数分布只是第一步。**噪声线以上的每一篇都要拉出命中原文逐条读**，
不能只看汇总数字就下「误判率 X%」的结论。逐篇归入四类之一：

| 判定 | 特征 | 处置 |
|---|---|---|
| 真命中 | 命中片段确实是模板套话、无源断言、空转表述 | 保留分数，不动阈值 |
| 体裁误配 | JD／战略规划／会议纪要／需求文档等术语密集体裁，命中词是领域术语（闭环、一体化、赋能、打造） | **判为真命中，保留分数，不豁免。** 这是用户拍板口径，见下 |
| 噪声 | 命中样本被残留格式符污染（`****`、换行断裂），或统计类 pattern 在过短文本上触发 | 不算证据；先修解析或加最小样本量 |
| 确认 bug | 正则在常见复合词内部命中子串 | 修正则，重跑全部基线 |

报给用户时必须**逐篇给全事实**，不能用「那几篇」「若干条」带过：标题、分数、字数、
命中模式及次数/密度、**被命中的原句**、文档链接。并明确区分「我的判断（推断）」与
「实测复现」——正则 bug 属实测；口径问题要请用户拍板，不要替他定。
汇总结论要标注为推断而非核实结果。

**报数量前先跑代码数一遍。** 灰区篇数、命中数、0 分篇数这类数字必须从刚才那次运行
的输出里取，不能凭印象写。「大概十篇」写出去、下一轮再改成「实际十二篇」，
比一开始多跑一行 `len()` 贵得多，而且会让他对你上一轮的其他数字一起失信任。

**已拍板口径（检测层与改写层分开）**：
- **检测层**：企业文书腔（「赋能」「打造」「进行+动词」「闭环」）超过密度阈值且附近无具体数字时，在**内部工作文档里也按 AI 腔计分**，不做体裁豁免、不降权（正常密度的业务文档因低于密度阈值或有具体数字托底，仍得低分）。
- **改写层**：看目标体裁决定改不改——正式合同、SOW、对外公告保留规范公文/商业术语；周报、复盘、纪要、随笔改成具体白话动作。
反之，命中被格式符污染的样本（`****`）或小样本统计量，仍按「噪声」处理。

## 坑

- 检测器是 **Python 3.9+**，本机用 `python3`。
- 相对路径 `scripts/detect_zh.py` 在用户项目下不解析——脚本在 skill 目录，先设 `DETECT` 绝对路径。
- 别把 `--clean` 的输出覆盖回 `.docx` / `.epub` / `.odt` / `.ipynb`——它输出的是纯文本，会毁掉文件。
- `extract_text` 直接吃 `.docx`（zipfile 路线），实测 ~/Downloads 15 篇真实中文 docx
  （SOW/需求/战略）全部抽到汉字、零误判；docx 场景不必先转 md。
- **别把高分当作者身份的证据**，更不能用来指控任何人——它描述文本，不描述人。
- **中文没有词边界，`\b` 不生效**——多字备选式 pattern 必须防「是某个常用复合词的后半段」。
  `据(?:统计|调查|研究)` 会在「数据**统计**」里命中「据统计」，把正常的「AGE数据统计」
  判成无源断言。写法是加负向后顾：`(?<![数依根证字单])据(?:统计|调查|研究)`。
  中文这类陷阱极多（「进行」「体系」「模型」「能力」都是高频词的组成部件），
  每加一条正则都要拿一批真实复合词反测。`11_unsourced_evidence` 已按此修好
  （后顾集 `(?<![数依根证字单])`，实测「AGE数据统计」「依据统计口径」「单据统计」
  不再误命中，「据研究」「据统计」「相关数据表明」仍命中）。
- **统计类判据（句长单调 / 段落等长）在过短文本上无统计意义**——`length_cv` 在 122 字上
  得 0.071 就能把分数抬到 25 分，纯属抽样噪声；3 句 [257,274,127]（127 与 274 差一倍）
  也会算出 cv=0.297 被判单调。**已按方案 A 实施：最小句数门槛 ≥3 → ≥5 句，
  不足 5 句返回 `cv=None`、不判单调、不计分。** 代价是短 AI 样本也失去该信号
  （分离度 29→28，`ai_slop_3` 48 分）。`段落长度一致` 同类问题，最小段数门槛仍为 4，未改。
- **改完 detector 或新建 skill 后必须重启 Hermes**：plugin 的 `_load_zh_detector`
  一旦置 `_zh_detector_loaded=True` 就永不重试；若首次加载时 skill 还没装好，
  中文文档会静默落到英文检测器（报 Boldface overuse / Curly quotes 这类英文标签
  打在中文明文档上），看起来像误判，其实是缓存过期。新起进程即恢复。
- 英文稿子用 `sloptrim` skill，不要用这个。
- 检测器复用上游 `sloptrim` 的字符层清洗（零宽字符、同形异码、非标准空格）。
  找不到上游时自动降级为内置实现，功能不丢，只是少了同形异码折叠。
  上游路径可用 `SLOPTRIM_DETECT_PY` 环境变量指定。

### 拿英文 `sloptrim` 跑中文：分数恒为 0，且不可作结论

对中文文本用上游 `sloptrim`（`scripts/detect.py`）会得到 `score 0 / clean`，但这不是“文本干净”，
而是**检测器根本没在分析中文**：

- `split_sentences` 只按西文 `.!?` 切句，`。；` 不算边界 ⇒ 全文只识别出十几到二十几「句」；
- `count_words` 用 `\b\w+\b`，中文一整段算 1 个「词」；
- 71 条 pattern 全是英文短语。

典型失败链（每一步都看不出错，直到看 metrics）：先直接跑 → 21 句、score 0；
再把 blocks 转成散文 → 21 句、score 0；再把中文标点归一化成西文 → 98 句、score 仍 0、
`patterns_flagged=1`（唯一命中是尾随空白，而那空白来自自己写的转换脚本，不是原文）。

**结论：`ai_tell_score=0 / clean` 对中文文档没有判别力，不能当质量结论交付。**

正确做法：**中文直接用本 skill 的 `detect_zh.py`**（中文分词、分句、17 类中文词表都已修好）。
只有在拿不到 `sloptrim-zh` 时才手工适配，且必须：

1. 先把待测文本重建为**可读散文**（飞书 blocks 每块一行时检测器按行断句，raw_content 直接喂也无效）；
2. 把 `。；：，、！？` 等全角标点归一化为西文，**只用于检测副本**，不改正文；
3. 拿到分数后**明确告知用户该分数对中文不具判别力**；
4. 改用英文 71 条模式目录做**中文适配人工核查**（脚本量化 + 逐条比对），
   把结论按「高/中/低」分级给出，并列出哪些模式不适用于中文（句长单调、段落等长、
   破折号、缩写、title case 等在中文里要么不存在要么是正常用法）。

不要在归一化后仍报一个看似权威的 `score 0`，那是把「没测到」说成「测过了」。

## 交付前自检

1. 检测器在最终文本上跑过；`ai_tell_score` 是 `clean` 或 `light tells`，
   否则说明更高档位的原因。
2. 没改平：`length_cv` ≥ 0.35，段落长度有起伏，激进档下口语词还在。
   稿子不足 5 句时 `length_cv` 是 `None`（设计上不判），此时只能用肉眼比句长起伏，
   **不要把「没有告警」当成「通过了」**——短文本上这个指标无统计意义，沉默不代表干净。
3. 字数 ≤ 原文 1.25 倍。
4. 原文的每个数字、人名、单位、日期、引用都还在，且挂在同一个名词上。
5. 没重写占位符，没删对冲，没加或删归属。
6. 代码块、引文、逐字引用里的零宽字符和非标准空格不误改。
